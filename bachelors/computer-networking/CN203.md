# CN203: Transport & Application Layer Protocols

In the second year of the Computer Networking program, students study the transport and application layers that enable end-to-end communication and support modern distributed applications. This course covers the evolution from traditional TCP/TLS to modern protocols like QUIC and HTTP/3, as well as specialized protocols for IoT, real-time communication, and cloud-native architectures.

## Course Overview

Transport & Application Layer Protocols builds on the foundational knowledge of the OSI model and TCP/IP architecture, focusing on how data is reliably transported across networks and how applications interact with the network stack. Students learn to evaluate, select, and implement appropriate transport and application protocols for various use cases, from high-performance computing to massive-scale IoT deployments.

## Detailed Syllabus

### Module 1: Transport Layer Evolution (8 hours)
- Limitations of TCP in modern networks (head-of-line blocking, congestion control issues)
- Introduction to QUIC: design goals, connection migration, zero-round-trip time (0-RTT)
- QUIC packet structure, frame types, and congestion control approaches
- Comparison of TCP Cubic, BBR, and QUIC congestion control algorithms
- TLS 1.3 integration in QUIC and performance implications
- HTTP/3 as the primary application of QUIC

### Module 2: HTTP/3 and Web Performance (6 hours)
- HTTP/2 limitations that HTTP/3 addresses
- QPACK header compression in HTTP/3
- Server push vs. cache digest in HTTP/3
- Resource prioritization and weight scheduling
- HTTP/3 interception and middlebox challenges
- Deployment considerations: load balancers, CDNs, and firewalls
- Performance case studies: web browsing, video streaming, API calls

### Module 3: gRPC and Cloud-Native RPC (6 hours)
- Protocol Buffers (protobuf) syntax and evolution
- gRPC service definition language and code generation
- Streaming unary, server streaming, client streaming, and bidirectional streaming
- Load balancing and service discovery integration with gRPC
- Interceptors, authentication, and observability in gRPC
- gRPC-Web for browser-to-service communication
- Performance comparison: gRPC vs. REST/JSON vs. GraphQL

### Module 4: Message Queuing and IoT Protocols (8 hours)
- MQTT 5.0: enhanced features, reason strings, user properties, shared subscriptions
- MQTT-SN for sensor networks and MQTT over QUIC
- CoAP (Constrained Application Protocol) for resource-constrained devices
- CoAP observe pattern, block-wise transfer, and resource discovery
- AMQP 1.0 for enterprise messaging and IoT hubs
- NATS and Pulsar for cloud-native messaging
- Choosing between MQTT, CoAP, and HTTP for IoT applications

### Module 5: Real-Time Communication Protocols (6 hours)
- WebRTC architecture: peer-to-peer connections, media streams, and data channels
- SRTP and SCTP for secure real-time transport
- STUN, TURN, and ICE for NAT traversal
- WebSockets vs. Server-Sent Events vs. WebRTC for real-time web
- MQTT over WebSockets for web-based IoT dashboards
- Low-latency protocols: SRT, RIST, and NDI for video contribution

### Module 6: Application Layer Security and Privacy (6 hours)
- End-to-end encryption in application protocols (Signal Protocol, MLS)
- OAuth 2.0 and OpenID Connect for API authorization
- JWT tokens and their security considerations
- Certificate transparency and pinning in application layer
- Privacy-preserving protocols: HTTP proxying, Oblivious DNS over HTTPS
- GDPR and CCPA implications for application layer data handling

### Module 7: Network Programming and APIs (6 hours)
- Socket programming evolution: traditional sockets to async I/O (epoll, kqueue, io_uring)
- High-performance networking frameworks: DPDK, RDMA, and XDP
- gRPC code generation and stubs
- RESTful API design principles and OpenAPI specification
- Webhooks and event-driven architectures
- Service mesh integration with Istio and Linkerd

### Module 8: Emerging and Future Protocols (4 hours)
- QUIC version negotiation and future extensions
- HTTP/3 prioritization schemes and upcoming improvements
- MQTT 6.0: AI-native features and semantic payloads
- CoAP over QUIC for constrained environments
- Blockchain-based application protocols (IPFS, libp2p)
- Post-quantum secure application layer protocols

## Hands-On Laboratory Exercises

### Lab 1: QUIC and HTTP/3 Implementation
- Set up a QUIC server using lsquic or ngtcp2
- Measure connection establishment latency compared to TCP/TLS
- Implement connection migration by changing network interfaces
- Analyze Wireshark traces of QUIC version negotiation

### Lab 2: gRPC Microservices
- Define a protobuf service for inventory management
- Implement unary and streaming RPC calls in Python/Go
- Deploy with Kubernetes and configure Istio for traffic management
- Observe latency and throughput under various load patterns

### Lab 3: IoT Protocol Comparison
- Build a temperature sensor publisher using MQTT 5.0
- Implement the same sensor using CoAP over UDP
- Compare battery consumption, bandwidth usage, and reliability
- Integrate both protocols with a cloud IoT hub (AWS IoT Core or Azure IoT Hub)

### Lab 4: Real-Time Communication
- Create a WebRTC-based video chat application
- Implement TURN server for relay traffic in restrictive networks
- Measure jitter and packet loss under simulated network conditions
- Experiment with SRT for low-latency video streaming

### Lab 5: API Gateway and Service Mesh
- Deploy an REST API with Kong or Envoy as API gateway
- Implement rate limiting, authentication, and transformation policies
- Migrate to a service mesh architecture with mutual TLS
- Observe traffic shifting and failure injection capabilities

## Key Concepts and Theorems

### The End-to-End Principle Revisited
- Application layer protocols increasingly handle functions once reserved for lower layers (reliability, security, congestion control)
- Trade-offs between implementing functions in transport vs. application layer
- Middlebox ossification and the rise of encryption everywhere

### Congestion Control in the User Space
- Shift from kernel-based TCP congestion control to user-space algorithms in QUIC
- Programmable congestion control via pluggable modules
- Research directions: machine learning-based congestion control

### Semantic Communication
- Move beyond bit-level accuracy to meaning-preserving communication
- MQTT 6.0 and CoAP extensions for semantic payloads
- AI-driven protocol optimization for specific application semantics

### Privacy by Design in Protocols
- Built-in privacy features: connection ID rotation in QUIC, encrypted SNI
- Minimization of metadata leakage in application protocols
- Trade-offs between privacy, performance, and network manageability

## Learning Outcomes

Upon successful completion of this course, students will be able to:

1. **Analyze and Compare Protocols**: Evaluate transport and application layer protocols based on performance, security, scalability, and suitability for specific use cases.

2. **Implement Protocol Solutions**: Develop working implementations of modern protocols (QUIC, HTTP/3, gRPC, MQTT, CoAP) using industry-standard tools and libraries.

3. **Design Application Layer Architectures**: Select appropriate protocols and design communication patterns for microservices, IoT systems, and real-time applications.

4. **Troubleshoot Protocol Issues**: Diagnose and resolve common problems in protocol implementations using packet captures, logs, and monitoring tools.

5. **Evaluate Emerging Technologies**: Assess the potential impact of new protocol developments (QUIC extensions, HTTP/3 advances, MQTT 6.0) on future network architectures.

6. **Apply Security Best Practices**: Implement end-to-end encryption, authentication, and authorization in application layer protocols while considering performance trade-offs.

7. **Optimize for Performance**: Tune protocol parameters and implement application-level optimizations for latency, throughput, and resource efficiency.

8. **Communicate Technical Concepts**: Explain complex protocol mechanisms to both technical stakeholders and non-technical decision-makers.
